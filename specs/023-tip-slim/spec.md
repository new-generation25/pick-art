# Feature Specification: 제보 노출 줄이기 · 사이트는 로그인 · 동의 체크 통합

**Feature Branch**: `revive/2026-10` (명세 폴더 `specs/023-tip-slim`)

**Created**: 2026-11-27

**Status**: 운영 배포됨(2026-11-28, main 3f3f6b2). 일반 회원 화면 일부와 인스타그램 앱 안 브라우저 안내는 운영에서 아직 확인하지 못함(tasks T044)

**Input**: 운영자 원문(「피카 디자인」 세션이 전달, 2026-11-27) «피카 내에 제보하기 기능이나 내용이 너무 많은데 좀 줄일 수 있는지 검토» → «카톡은 채널구독, 피카에서는 로그인» → «동의 체크도 통합해서 줄여», «제보는 카톡과 앱에서만 직접 받는데». 근거 측정: `docs/design/tip_review_2026-11-28/hits.json`(디자인 세션 커밋 ea67ed4) — 홈·상세·소개·/partners 맨 아래마다 «숨은 행사 찾기» 띠와 꼬리말 «행사 제보하기·리플렛으로 알리기»가 겹쳐 나옴.

**이 명세의 범위**: 사이트 화면(A·B1·C1·C2). 카카오톡 채널 쪽(B2 채널 추가한 사람만 받기, C3 카카오톡 동의 문구)은 카카오 스킬 파일을 맡은 017 세션에 넘겼다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — 제보 안내가 화면마다 겹쳐 나오지 않는다 (Priority: P1)

방문자는 홈 맨 아래에서만 «숨은 행사 찾기» 띠를 본다. 행사 상세·소개·단체 안내 화면에는 띠가 없고, 꼬리말의 제보 링크는 «행사 제보하기» 하나다.

**Independent Test**: 폭 375px에서 홈, 행사 상세, `/about`, `/partners` 를 맨 아래까지 내려 띠와 꼬리말 링크를 센다.

**Acceptance Scenarios**:

1. **Given** 홈(`/`, 지역 홈 `/region/…`), **When** 맨 아래로 내린다, **Then** «숨은 행사 찾기» 띠가 한 번 보인다.
2. **Given** 행사 상세·`/about`·`/partners`·그 밖의 공개 화면, **When** 맨 아래로 내린다, **Then** 띠가 없다.
3. **Given** 어느 공개 화면이든, **When** 꼬리말을 본다, **Then** 제보 링크는 «행사 제보하기» 하나이고 «리플렛으로 알리기»는 없다(`/partners` 본문에는 남는다).
4. **Given** 행사 상세, **When** 아래쪽을 본다, **Then** 알리는 수단은 «정보가 틀렸어요»(오류 신고)뿐이다.

### User Story 2 — «내 정보»와 제보 화면이 짧아진다 (Priority: P2)

제보한 적도 포인트도 없는 회원의 «내 정보»에는 «활동 포인트» 카드가 없다. «카카오톡 제보 연결» 카드는 맨 아래 계정 정보 쪽에 있다. `/tip` 은 쿠폰 설명이 한 줄이고 접힌 칸이 «더 알려 주기»와 «선택 항목» 둘이다.

**Independent Test**: 제보·포인트가 없는 회원으로 `/me` 를 열어 카드 순서를 보고, `/tip` 의 접힌 칸 수를 센다.

### User Story 3 — 사이트에서 보내는 것은 모두 로그인 뒤에 (Priority: P1)

협약 신청도 제보·리플렛처럼 로그인한 사람만 보낸다. 인스타그램 같은 앱 안 브라우저에서는 구글 로그인이 막히므로, 그런 브라우저로 보이면 «외부 브라우저(크롬·사파리)로 열기» 안내를 먼저 보여 준다.

**Independent Test**: 로그인하지 않고 `/partners#join` 을 열면 신청 칸 대신 로그인 버튼이 보이고, 누르면 로그인 화면으로 간다. 로그인하지 않은 요청으로 신청 함수를 부르면 거절된다.

### User Story 4 — 필수 동의 체크가 하나 (Priority: P1)

협약 신청의 필수 체크는 맨 위 «전체 동의» 하나다. 그 아래에 게재·자동 수집·사실과 권리 확인·담당 연락처(개인정보) 네 항목이 한 줄씩 보이고, 개인정보 항목은 따로 구분돼 보인다. 이미지 사용은 동의가 아니라 고르는 것이라 그대로 둔다. 리플렛 등록의 권리 확인 체크는 둘에서 하나가 된다.

**Independent Test**: 협약 신청 화면의 필수 체크박스가 1개, 리플렛 등록 화면의 체크박스가 1개인지 센다. 체크하지 않고 보내면 까닭이 보이고 보내지지 않는다.

### Edge Cases

- 로그인 없이 이미 보낸 협약 신청(운영 3건)은 그대로 둔다. 새 신청만 로그인이 필요하다.
- 앱 안 브라우저인지 알 수 없으면(낯선 앱) 안내 없이 로그인 버튼만 보인다.
- 포인트가 0이어도 보낸 제보가 있으면 «활동 포인트» 카드를 보인다(확인 중인 제보가 있는 회원).
- `/me#points` 로 들어왔는데 카드가 없는 회원은 화면 맨 위가 보인다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: «숨은 행사 찾기» 띠는 홈(`/`, `/region/…`)에만 보인다.
- **FR-002**: 꼬리말의 제보 링크는 «행사 제보하기» 하나다. «리플렛으로 알리기»는 `/partners` 본문에만 있다.
- **FR-003**: «내 정보»의 «활동 포인트» 카드는 포인트 기록이나 보낸 제보가 있는 회원에게만 보인다. «카카오톡 제보 연결» 카드는 계정 정보 카드 바로 위(맨 아래 쪽)에 둔다.
- **FR-004**: `/tip` 머리말의 쿠폰 설명은 한 줄이고, «커피 쿠폰 받기»와 «이름 남기기»는 «선택 항목» 접힌 칸 하나로 합친다. 쿠폰 연락처 동의 체크는 그 안에 그대로 둔다.
- **FR-005**: 협약 신청은 로그인한 사람만 보낼 수 있다. 화면은 로그인 버튼을 보이고, 신청 함수는 로그인하지 않은 요청을 거절한다.
- **FR-006**: 앱 안 브라우저(인스타그램·페이스북·카카오톡·네이버·라인 앱 안, 안드로이드 웹뷰)로 보이면 로그인 버튼 앞에 «외부 브라우저로 열기» 안내와 주소 복사 단추를 보인다(로그인 화면, 제보·리플렛·협약 신청의 로그인 안내).
- **FR-007**: 협약 신청의 필수 체크는 «전체 동의» 하나이고, 네 항목(게재, 자동 수집, 사실·권리 확인, 담당 연락처 이용)이 그 아래 목록으로 보인다. 담당 연락처(개인정보) 항목은 수집 항목·목적·보유 기간과 함께 따로 구분해 보인다. 동의서 전문은 펼쳐 볼 수 있다. 저장되는 동의 값(네 항목 모두 동의)과 동의서 판 기록은 유지한다.
- **FR-008**: 리플렛 등록의 권리 확인 체크는 하나(«보낸 정보가 사실이고, 이미지 권리를 확인했어요»)이고, 풀이 문장은 그 아래에 보인다. 문구 판을 올려 저장한다.

## Success Criteria *(mandatory)*

- **SC-001**: 폭 375px에서 행사 상세·`/about`·`/partners` 맨 아래에 제보 띠가 0개, 홈에 1개.
- **SC-002**: 모든 공개 화면 꼬리말의 제보 링크가 1개.
- **SC-003**: 로그인하지 않은 상태에서 협약 신청을 누르면 로그인 화면으로 가고, 로그인하지 않은 신청 요청은 100% 거절된다.
- **SC-004**: 협약 신청의 필수 체크박스 1개, 리플렛 등록의 체크박스 1개.
- **SC-005**: 폭 375px에서 바뀐 화면의 가로 넘침 0.

## Assumptions

- «홈»에는 지역 홈(`/region/…`)을 넣었다. 내 지역이 있는 사람은 `/` 대신 그 화면을 홈으로 보기 때문이다.
- 행사 상세에는 띠 말고 제보를 권하는 자리가 없었다. «제보: ○○»(제보한 분 이름) 줄은 권유가 아니라 출처 표시라 그대로 둔다.
- 협약 동의서는 아직 법률 검토 전 초안이다(`IS_DRAFT`). «전체 동의» 하나로 묶는 방식이 개인정보 동의로 충분한지는 법률 검토 때 함께 본다.
- 인스타그램 앱 안 브라우저에서 카카오 로그인이 되는지는 이 PC에서 확인할 수 없다(휴대폰 인스타그램 앱이 있어야 함). 운영자 휴대폰 확인 항목으로 남긴다.
