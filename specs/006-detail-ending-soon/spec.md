# Feature Specification: 상세 정보 보강과 「곧 끝남」

**Feature Branch**: `revive/2026-10` (명세 `specs/006-detail-ending-soon`) | **Created**: 2026-11-26 | **Status**: Draft

**Input**: 운영자(11/26) "공공데이터에서 가져오는 내용들은 조금더 우리의 데이터를 자세하게 추가할 필요가 있네", "피카가 가져올 기능추가 모두 적용" — 벤치마킹 리포트의 「곧 끝남」(공다방 «오늘 마감», Tokyo Art Beat «7일 안에 끝남»)과 «공식 출처 링크 나란히»(Time Out «Event website»). 묶음 나누기: [docs/plan/benchmark_features_2026-11-26.md](../../docs/plan/benchmark_features_2026-11-26.md)

## User Scenarios & Testing

### User Story 1 - 공연 상세에서 필요한 정보를 칸으로 본다 (P1)

KOPIS 공연 상세의 정보 표에 «공연 시각», «러닝타임», «출연», «장르»가 칸으로 나온다. 지금은 같은 내용이 «상세 안내» 글 속에 묻혀 있다.

**Independent Test**: KOPIS 공연 상세에 네 칸이 원문 값 그대로 있고, «상세 안내»에 같은 줄이 다시 나오지 않으면 통과.

### User Story 2 - 곧 끝나는 전시·행사를 놓치지 않는다 (P1)

7일 넘게 하는 전시·행사가 7일 안에 끝나면 카드에 「곧 끝남」 표시가 붙고, 홈 «언제» 필터의 「곧 끝남」으로 그것만 모아 볼 수 있다.

**Independent Test**: 「곧 끝남」 목록의 모든 행사가 «기간 7일 이상 + 끝나는 날이 오늘~7일 뒤»이면 통과(11/26 기준 약 25건).

### User Story 3 - 공식 안내로 바로 간다 (P2)

상세 정보 표의 «출처» 칸이 공식 안내 페이지 링크다(위쪽 «원본 안내 페이지 열기» 버튼과 같은 곳).

### Edge Cases

- 설명에 라벨 줄이 없는 행사(기관 게시판·인스타) → 칸을 만들지 않고 설명을 그대로 둔다.
- «일시: 금요일(19:30), 토요일(11:00,14:00,16:30)»처럼 여러 회차 → 원문 그대로 한 칸.
- 하루짜리 행사는 「곧 끝남」 대상이 아니다(날짜가 이미 주인공).

## Requirements

- **FR-001**: 설명의 줄 머리 «일시·러닝타임·출연·장르: 값»을 칸으로 보인다(공연 시각·러닝타임·출연·장르). 원문을 바꾸지 않는다(헌장 I).
- **FR-002**: 칸으로 옮긴 줄과 이미 칸이 있는 줄(관람료·관람연령)은 «상세 안내»에서 뺀다. 남는 글이 없으면 지금의 안내 문구를 쓴다.
- **FR-003**: 「곧 끝남」 = 기간 7일 이상 + 끝나는 날이 오늘~7일 뒤. 카드 표시와 홈 «언제» 필터 값으로 둔다(주소에 남음).
- **FR-004**: 정보 표의 «출처» 값은 원본 주소 링크(새 창).
- **FR-005**: 브랜드 가이드의 기존 칩·표 모양을 쓴다. 날짜가 여전히 가장 큰 정보다.

## Success Criteria

- **SC-001**: 11/26 활성 KOPIS 305건 중 일시 305·러닝타임 286·출연 209건에 칸이 생긴다(설명 기준과 같은 수).
- **SC-002**: 「곧 끝남」 목록에 조건 밖 행사 0건.

## Assumptions

- 스키마·수집기 변경 없음(설명에 이미 있음). KOPIS 상세 API를 다시 부르지 않는다.
- 공다방의 «규모·대상(가족·연인)»은 원문에 없어서 만들지 않는다. 대상 중 아이는 004가 맡는다.
