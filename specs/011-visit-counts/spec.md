# Feature Specification: 방문 수와 행사별 조회·클릭 집계

**Feature Branch**: `revive/2026-10` (명세 `specs/011-visit-counts`) | **Created**: 2026-11-26 | **Status**: 구현·로컬 검증 완료 — 운영자 11/26 «모두 진행해»(시장조사 세션 입력, 기록 확인). Vercel 토큰 자동 표시는 하지 않음(관리자 화면에 Vercel Analytics 링크)

**Input**: 시장조사 세션 요청(사용자 11/26 「앱 개선에 넘겨」). 지원금(로컬기업 육성사업 동남권)·문화재단 용역에 낼 실적 숫자(방문자)와, 단체에게 줄 «월간 노출·클릭 증빙»(specs/012)의 바탕. 조건: 쿠키 없음, 관객 개인 단위 기록 없음(«방문 수만 셉니다»).

## 지금 상태 (2026-11-26 확인, 정정)

- Vercel Web Analytics는 켜져 있고 숫자가 쌓이고 있다(시장조사 세션이 운영자 Chrome으로 대시보드 확인: 팀 Pro, 최근 7일 방문자 28·페이지뷰 74, 커스텀 이벤트 없음).
- 처음에 «켜져 있지 않다»고 적은 것은 틀렸다. 이 세션의 Vercel 연결(MCP)로는 같은 팀의 다른 프로젝트 3개만 보이고 pick-art가 보이지 않는다 — API 404는 이 연결의 권한 문제다.
- 행사별 조회 수·«원본 안내 페이지 열기» 클릭 수는 어디에도 세지 않는다.

## User Stories

1. **월간 방문자 (P1)** — 운영자가 관리자 화면에서 월별 방문자 수·페이지 조회 수, 많이 본 페이지 10개, 들어온 곳(검색·인스타 등)을 본다.
2. **행사별 조회·클릭 (P1)** — 행사마다 하루 단위로 «상세 조회», «원본 안내 페이지 열기», «캘린더 추가», «공유»를 센다. 사람·기기는 구분하지 않는다(숫자만).
3. **증빙 내보내기 (P2)** — 단체·장소·월을 고르면 그 달 행사별 «노출(상세 조회)·클릭(원본·캘린더·공유)»을 표로 내려받는다(specs/012 단체 페이지와 같이). 표기는 «노출·클릭», 예매 전환은 모른다고 적는다.

## 요구사항

- FR-001 방문자 수는 Vercel Web Analytics(쿠키 없음, 개인 식별 저장 없음)로 센다. 수집기가 하루 한 번 API로 읽어 `ops_snapshots`(`site_visits`)에 올리고 대시보드가 읽는다. API로 읽으려면 pick-art를 볼 수 있는 Vercel 토큰이 필요하다(운영자가 만들어 `collector/.env.local`에 넣음).
- FR-002 행사별 숫자는 자체 집계 표 `event_counts_daily(event_id, day, kind, n)` — kind: view · outbound · calendar · share. 화면이 `/api/count`로 한 번 보내면 서버가 `n`을 1 올린다. IP·기기·쿠키·로그인 정보를 저장하지 않는다. 봇(User-Agent)과 관리자 접속은 세지 않는다.
- FR-003 공개 읽기 없음. 관리자만 읽기(RLS). 쓰기는 서버 함수(security definer)로만.
- FR-004 개인정보처리방침에 «방문 수와 행사별 조회·클릭 수를 날짜별 숫자로만 센다, 개인을 알아볼 수 있는 정보는 남기지 않는다»를 넣는다.

## 끝 조건

- 관리자 화면에 지난 30일 방문자·조회 수가 Vercel 화면 숫자와 같음
- 시험 행사 상세를 3번 열고 원본 버튼을 1번 누르면 그날 view 3·outbound 1 (봇 UA로 연 것은 0)
- 익명으로 `event_counts_daily` 읽기 `[]`
- 표에 IP·UA·사용자 칸이 없음(스키마로 확인)

## 정할 것 (운영자)

1. 방문자 숫자를 관리자 화면에 자동으로 올릴지 — 올리려면 pick-art를 읽을 수 있는 Vercel 토큰(읽기용)을 운영자가 만들어야 한다. 아니면 운영자가 Vercel 대시보드에서 직접 본다.
2. 새 표 `event_counts_daily` 만들기(마이그레이션) 승인.
3. 개인정보처리방침 문구 추가 승인.

## 구현 (2026-11-26)

- 마이그레이션 `20261126060000_counts_orgs.sql`(적용): `event_counts_daily` + `count_event(p_event, p_kind)`(security definer — 공개 행사만, 관리자 접속 제외, 한국 날짜). 익명: 표 읽기 `[]`, 직접 넣기 401, 함수 호출 204.
- 화면: 상세 열면 view(같은 창 새로 고침은 한 번만 — sessionStorage, 서버로 보내지 않음), «원본 안내 페이지 열기»·출처 줄 링크 outbound, 캘린더 구글·.ics calendar, 공유 share. 봇 UA·자동화 브라우저는 세지 않음(`lib/countEvent.ts`).
- 관리자 «노출·클릭»(`/admin/counts`): 달·단체(012) 고르기, 행사별 표, CSV 내려받기(엑셀 한글 BOM), Vercel Analytics 링크.
- 개인정보처리방침: 수집 항목 2줄(행사별 조회·클릭 수, 방문 통계), 보유 기간 1줄, 변경 고지 이력 1줄.

## 검증 (로컬 `next start`, 11/26)

- 익명으로 상세를 두 번 열고 원본 버튼·구글 캘린더를 누름 → view 1 · outbound 1 · calendar 1
- 관리자(pick.art.pica)로 같은 상세를 연 뒤에도 view 1 그대로, `/admin/counts`에 «노출 1 · 클릭 2»
- 시험 숫자는 지움. `src/lib/__tests__/eventCounts.test.mjs` 3개 통과

## 남은 것

- 개인정보처리방침은 «바꾸면 시행 7일 전부터 알린다»고 적혀 있다. 이번 줄은 사람을 알아볼 수 없는 숫자라 처리 범위가 바뀌지 않는다고 보고 이력에 적었다 — 운영자 확인 필요.

## FR-001 방문자 자동 표시 (2026-11-26 추가)

- 운영자 11/26 «네가 만들어 넣어»(시장조사 세션 입력, 기록 확인): 시장조사 세션이 pick-art 프로젝트만 읽는 Vercel 토큰(«pica collector visits», 2027-11-26 만료)을 `collector/.env.local`의 `VERCEL_TOKEN`에 넣음. 사이트(프론트)에는 두지 않는다.
- `collector/tools/publish_site_visits.py`: Vercel Web Analytics API(`/v1/query/web-analytics/visits/count`·`aggregate`)로 7일·30일·이번 달 합계, 30일 날짜별, 6개월 월별, 30일 많이 본 페이지·들어온 곳·기기를 읽어 `ops_snapshots('site_visits')`에 올린다. 정기 실행(main.py)에서 하루 두 번. 날짜는 UTC 단위.
- 관리자 대시보드 «사이트 방문» 칸(`components/admin/SiteVisitsPanel.tsx`).
- 확인(11/26): 도구 실행 «7일 35명·94뷰 · 30일 39명·98뷰», 로컬 관리자 화면에 같은 숫자·페이지·유입·기기 표시.
- 토큰이 만료되면(2027-11-26) 대시보드에 숫자가 멈추고 정기 실행 보고에 «Vercel 응답 401/403 — 토큰 만료·권한 확인»이 나온다.
