# 016 예술가·작은 단체 안내(/partners) + 정보 제공 동의(정식 협약) 받기

**Created**: 2026-11-26
**Input**: 운영자(11/26) «이후로는 실제 서비스 설명과 동의 페이지를 통한 동의(정식 협약) 수집», «동의페이지 안내 하기 전에 동의 페이지를 더 잘 완성해야지», 최종 «그렇게 해»(/partners를 예술가·작은 단체용으로 다듬고 끝에 동의 칸). SNS콘텐츠 제작 세션이 전달.
**근거 문서**: docs/partner/동의서_초안.md (초안 · 법률 검토 전), docs/INSTA_ENGAGE.md(허락 3단계), docs/BRAND_GUIDE.md

## 배경

인스타 허락은 세 단계다: 임시 동의(행사 한 건) → 실제 동의(앞으로의 소식, whitelist «상시동의:») → **정식 협약(동의서)**.
대상별 자료: 공기관 = 협업제안서 PDF, 소비자 = /about, 예술가·작은 단체 = /partners. 그런데 /partners 첫머리가 KOPIS·공연법 설명과 «722건 중 395건» 통계라 기관 제안서처럼 읽히고, 동의 받을 칸이 없었다(«메일로… 신청 양식은 준비 중»).
허락 상대는 주로 개인 예술가·작은 극단·동네 갤러리이고, 대부분 휴대폰에서 인스타 링크로 들어온다.

## 사용자 이야기

### US1 예술가가 휴대폰으로 읽고 동의를 보낸다 (P1)
/partners 순서: 피카가 뭔지 한 줄 → «이렇게 실려요»(실제 카드 모양 예시, 이름 가림) → «하실 일은 이 정도» 3단계 → 실리면 생기는 것 → 약속 → **동의하고 실리기(#join)** → 자주 묻는 것 → (접힘) 기관 담당자용 설명.

- 동의 칸: ① 동의 요약 3개(게재·자동 수집 체크, 이미지 쓰기/글만 고르기) ② 필수 칸 3개(단체·활동 이름, 공식 SNS·누리집, 담당 연락처 비공개) + «더 적기(선택)» 접힘 ③ 확인 2개(단체 확인 사항, 연락처 수집·이용) + «동의서 전문 보기(초안)» 접힘.
- **로그인 없이 보낸다.** 인스타 앱 안 브라우저에서는 구글 로그인이 막혀서다. 로그인해 있으면 «내가 보낸 신청»과 «철회 요청»이 보인다.
- 보내면 «받았어요» + 다음에 일어날 일(운영자 확인, 일주일 안 연락, 협약 표시, 철회 방법).
- 필수 동의가 빠지면 보내지 않고 무엇이 빠졌는지 알린다.

### US2 운영자가 확인하고 정식 협약으로 표시한다 (P1)
/admin/partners 에서 신청을 읽고, 단체(orgs)를 찾아 연결하거나 새로 만들고 «협약 확인».
- «협약 확인» → 신청 confirmed, 단체 `partner_since` = 오늘(이미 있으면 그대로), `partner_note` 에 신청 id·문구 버전, 인스타 계정이 단체에 비어 있으면 채움.
- «반려»는 메모와 함께. 관리자 첫 화면에 «협약 신청·철회 요청 N건 확인 대기».

### US3 철회 (P2)
회원은 «철회 요청», 누구나 메일. 운영자 «철회 처리» → 신청 withdrawn, 단체 `partner_since` 비움, `partner_note` 에 철회 날짜.

## 기능 요구

- **FR-001** 표 `partner_agreements`(마이그레이션 20261127040000·050000·060000). 대표자·user_id 는 비어도 된다.
- **FR-002** 보내기는 함수 `submit_partner_agreement(jsonb)`로만 받는다(익명·회원 모두). 익명은 사이트 전체 하루 20건, 회원은 하루 3건, 같은 이름+연락처는 하루 한 번. IP 등 접속 정보는 저장하지 않는다. 화면에 숨은 칸(자동 프로그램 거르기)을 둔다.
- **FR-003** 읽기: 회원은 자기 것, 관리자는 전부. 익명은 표를 읽지 못한다. 상태·단체 연결은 관리자만 바꾼다. 필수 동의 false 는 표 CHECK 가 거절한다.
- **FR-004** 동의서 문구·요약·제출 뒤 안내·문구 버전·«초안» 표시는 `frontend/src/lib/partnerAgreement.ts` 한곳에만. 검토 뒤 이 파일만 고치고 버전을 올린다.
- **FR-005** 담당 연락처는 관리자만 본다. 개인정보처리방침에 수집 항목·목적·보관 기간.
- **FR-006** 모바일 우선: 칸 높이 44px 이상, 글자 16px(휴대폰 확대 방지), 법률 문구는 접기. 브랜드 가이드 색·말투(해요체, 짧게), 지역은 시군 이름(«경남»을 내세우지 않음). 예시는 이름 가린 예시(동의받은 단체 예시가 생기면 교체).
- **FR-007** 기관용 설명(KOPIS·공연법·395/722)은 지우지 않고 맨 아래 접는 칸으로 옮긴다.

## 성공 기준

- 휴대폰에서 동의 칸까지 읽고 보내는 데 3분 이내. 보낸 신청이 관리자 화면에 바로 보이고, 협약 확인까지 이어진다.
- 익명은 표를 읽지 못하고, 필수 동의 false 는 DB가 거절한다.
- **운영자가 휴대폰 화면 캡처와 확인용 링크로 검토·승인한 뒤 배포**한다. 승인 전에는 인스타 문안에 주소를 넣지 않는다(SNS콘텐츠 제작 세션이 막아 둠).

## 범위 밖 / 가정

- 전자서명·본인 확인(인스타 계정 주인 확인)은 하지 않는다.
- 정식 협약 단체를 whitelist «상시동의:»로 자동 표시하지 않는다(운영자가 맞춘다).
- 운영 주체 이름은 사업자등록 전이라 비워 둔다(초안 «확인 필요» 그대로).
- 동의서 원본의 사이트 주소 pick-art.vercel.app 은 지금 주소 picka.news 로 적었다. «서명한 날부터 1년»은 온라인이라 «피카가 확인한 날부터 1년»으로 적었다(초안 원본 문서는 고치지 않음).

## 덧붙임 — 개인/단체 구분 (2026-11-28)

운영자: «파트너 협약할때 단체인지 개인인지 구분하는게 좋을까?» → «넣어». 그때까지 협약을 맺은 4곳이 모두 «단체»로 저장돼 있었는데 화가 개인도 있었다.

- 신청 양식 «② 누구인가요» 맨 위에서 «개인(작가·연주자) / 단체·공간» 하나를 꼭 고른다. 개인이면 이름표가 «활동 이름», «더 적기»에서 대표자·고유번호 칸이 보이지 않는다. 단체이면 동의 목록에 «권한 · 단체를 대표해 동의할 수 있어요» 한 줄이 더 보인다(«전체 동의» 체크 하나는 그대로).
- 신청마다 구분(`partner_agreements.applicant_type`: person / org)을 저장한다. 그 전 신청은 비어 있다.
- 운영자가 «협약 확인»에서 새 줄을 만들면 단체 표의 구분이 «개인» 또는 «단체»로 들어간다(`orgs.kind` 에 «개인» 추가). 단체 페이지는 «예술가», 협약 표시는 «협약 예술가»로 보인다.
- DB: `supabase/migrations/20261128030000_partner_applicant_type.sql`. 동의서 판 `2026-11-28-draft`.
- «권한» 한 줄은 법률 검토 전 문구다(동의서 초안과 같이 검토한다).
