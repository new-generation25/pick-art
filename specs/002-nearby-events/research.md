# Research: 내 주변 행사 (거리순 보기)

작성 2026-11-21. 실측 근거는 각 항목에 적었다. 확인하지 못한 것은 「구현 첫 작업에서 확인」으로 표시했다.

## 0. 현재 데이터 실측 (2026-11-21, 운영 DB 읽기)

- 공개(`PUBLISHED`) 중이고 끝나지 않은 행사 **692건**, 서로 다른 `venue` 글자 **200개**, `venue`가 빈 행사 **15건**.
- 같은 장소가 여러 표기로 들어 있다: `해운대문화회관 (고운홀)` · `해운대문화회관\xa0고운홀` · `해운대문화회관\xa0해운홀`, `3·15아트홀 제3전시실` · `창원문화재단 3·15 아트홀 제2전시실`.
  → 괄호·관(홀·전시실) 이름·특수 공백·운영 기관 머리(「창원문화재단」)를 떼어 **건물 단위**로 묶으면 **199개 표기 → 133곳**(2026-11-21 `collector/venue_norm.py`로 실측, T005).
- `events`에는 좌표 칸이 없다. KOPIS 수집분은 `raw_posts.content.ai_suggestion.address`에 시설 주소가 있다.

## 1. 장소 좌표를 어디서 얻나

- **Decision**: ① KOPIS 공연시설 상세(`prfplc/{mt10id}`)의 위도·경도 → ② 네이버 지역 검색 API(장소명 검색) → ③ 운영자 수동 입력, 순서로 채운다. 좌표는 `venues` 표에 장소마다 한 번만 저장한다.
- **Rationale**: 헌장 IV(공식 API 먼저, 비용 0). KOPIS는 이미 쓰는 공식 API이고 시설 단위라 같은 공연장이 반복돼도 한 번이면 된다. 길찾기를 네이버지도로 넘기므로(FR-013) 좌표도 같은 네이버 데이터에서 얻어 피카의 위치와 네이버지도가 잡는 위치를 맞춘다(2026-11-21 운영자 결정: 카카오 대신 네이버로 통일). 100곳 안팎 백필과 하루 수 건 신규는 무료 한도 안으로 예상한다.
- **확인 결과(2026-11-21, T002·T003)**:
  - **(정정 2026-11-21)** 네이버 개발자센터의 신규 등록 목록에 「검색」이 없다(운영자 화면 확인). 지역 검색은 **NAVER API HUB**(네이버 클라우드 콘솔 console.ncloud.com/naver-api-hub)로 옮겨졌다 — 공식 문서 api.ncloud-docs.com/docs/naver-api-hub-search-local: `GET https://naverapihub.apigw.ntruss.com/search/v1/local?query=…&display=…&format=json`, 인증 헤더 `X-NCP-APIGW-API-KEY-ID`·`X-NCP-APIGW-API-KEY`(Application의 Client ID·Secret), `mapx`=경도·`mapy`=위도(WGS84). 「한시적 무료, 유료 전환 시 사전 공지」(가이드 개요), 무료 기간 월 호출 한도 API별 50,000건(가이드 FAQ). 133곳 백필은 한도의 0.3%.
  - (옛 기록) 네이버 지역 검색: 개발자센터 문서 기준 검색 API 하루 호출 한도 **25,000회**, `mapx`·`mapy`는 **WGS84 기준**(실제 값은 경위도 × 10⁷ 정수로 알려져 있음 — 키 발급 뒤 실제 응답으로 최종 확인, `naver_to_wgs84`가 한국 범위 밖 값은 거부). 133곳 백필과 하루 수 건 신규는 한도의 1% 미만.
  - KOPIS `prfplc` 좌표: **확인 못 함** — 2026-11-21 새벽 이 PC의 요청이 KOPIS에서 「Request Blocked」(HTTP 400)로 막혔다(requests·aiohttp 모두). 좌표 칸이 확인되면 보조 출처로 붙이고, 그전에는 네이버 지역 검색만으로 진행한다.
- **Alternatives**: 카카오 로컬(장소명 검색 품질 좋음, 키 하나 더 관리 — 운영자 결정으로 제외), 네이버 클라우드 Geocoding(주소만 받음, 지역 검색에서 주소가 나오면 보조로 검토), 구글 Geocoding(유료) — 채택 안 함.

## 2. 자동 확정 기준 (헌장 I: 확인한 것만)

- **Decision**: 다음을 모두 만족할 때만 `confirmed`로 자동 확정, 아니면 `pending`(운영자 확인 대기).
  1. 좌표가 부산·경남 경계 상자 안이고, 결과 주소의 시군이 행사 `region`과 같다.
  2. KOPIS 좌표이거나, 네이버 지역 검색 1순위 결과의 장소명이 정규화한 장소명을 포함(또는 그 반대)한다.
  3. 검색 후보가 2개 이상이면 1·2순위 거리 차가 300m 이내(같은 건물)일 때만.
- 후보는 `venues.candidates`에 최대 3개 저장해 관리자 화면에서 고르게 한다.
- **Rationale**: SC-002(오차 300m) 보장, 「OO카페」류 오매칭 방지.

## 3. 거리 계산 위치와 방식

- **Decision**: 방문자 브라우저 안에서 하버사인(직선거리)으로 계산한다. 서버로 위치를 보내지 않는다(FR-003). 목록 데이터(행사 + 장소 좌표)는 서버에서 날짜 조건으로 한 번 받아온다.
- **Rationale**: 대상이 기간 안 행사 수백 건이라 브라우저 계산으로 충분(수 ms). 위치를 서버·URL·분석 도구에 남기지 않는다. Vercel Analytics는 URL을 기록하므로 **좌표를 URL 쿼리에 넣지 않는다**(지역 이름만 URL에 둘 수 있다).
- **Alternatives**: DB에서 PostGIS로 거리 정렬 — 위치를 서버로 보내야 해서 기각.

## 4. 위치 권한·실패 처리

- **Decision**: 브라우저 Geolocation API를 「내 주변」 화면에서 버튼을 누를 때만 호출(페이지 열자마자 묻지 않음). 정확도 낮음 `maximumAge` 5분 · `timeout` 6초. 실패·거부·6초 초과면 지역 선택으로 전환.
- 정확도(`coords.accuracy`)가 1km를 넘으면 거리 앞에 「약」을 붙이고 지역 선택을 함께 권한다.
- https에서만 동작한다(운영 사이트는 https, 로컬 개발은 localhost라 허용됨).

## 5. 지역 기준점

- **Decision**: 경남 18개 시군 + 부산 16개 구·군의 기준점을 **각 시청·구청·군청 좌표**로 정적 파일에 둔다(`frontend/src/lib/areaCenters.ts`). 좌표는 네이버 지역 검색으로 관공서를 찾아 한 번 만들고 출처를 주석에 적는다.
- **Rationale**: 사람이 「○○ 중심」으로 납득하는 지점이고 바뀌지 않는다. 기존 `GN_REGIONS`(시군 + 부산)와 이름을 맞추고, 부산은 구·군 단위를 추가한다.

## 6. 네이버지도 길찾기 연결 (FR-013)

- **Decision**:
  - 휴대폰: 앱 스킴 `nmap://route/public?dlat={lat}&dlng={lng}&dname={장소명}&appname={사이트 도메인}`(대중교통), `nmap://route/car?…`(자동차). 출발지를 비우면 앱이 현재 위치를 쓴다.
  - 앱이 없거나 PC: 네이버지도 웹으로 연다. 좌표 기반 웹 길찾기 주소 형식은 구현 첫 작업에서 실제로 열어 확인하고, 확인이 안 되면 **장소 이름 검색 주소**(`https://map.naver.com/p/search/{장소명}`)로 연다.
  - 좌표가 없는 장소는 장소 이름 검색으로 연다.
- **확인 결과(2026-11-21, T004)**: 네이버 클라우드 「Maps URL Scheme」 문서(guide.ncloud-docs.com/docs/maps-url-scheme)에서 `nmap://route/public?slat=…&dlat=…&dlng=…&dname=…&appname=…` 형식과 **`appname` 필수**를 확인했다. 안드로이드는 `intent://…#Intent;scheme=nmap;…;package=com.nhn.android.nmap;end` 형식으로 열면 앱이 없을 때 스토어로 간다. 출발지(`slat` 등)는 생략한다. 좌표 기반 **웹** 길찾기 주소는 공식 문서로 확인하지 못해, 앱이 없을 때·PC에서는 장소 이름 검색 주소로 연다. 실기기 확인은 T031.
- **Rationale**: 운영자 결정(2026-11-21) — 이동시간은 피카가 계산하지 않고 네이버지도에 맡긴다. 피카는 출발지(방문자 위치)를 넘기지 않는다.

## 7. 비밀값

- 네이버 검색 키(Client ID·Secret)는 **수집기 쪽(`collector/.env`)에만** 둔다. 프런트·Vercel에는 넣지 않는다(헌장 III). 관리자 화면의 후보 선택은 수집기가 미리 저장한 `candidates`를 고르는 방식이라 프런트에 키가 필요 없다.
- 사용자 할 일: 네이버 클라우드 콘솔 NAVER API HUB에서 「지역 검색」 이용 신청 → Application 등록 → 인증정보(Client ID·Secret) 확인 → `collector/.env`에 넣기(내가 대신 할 수 없음 — 계정 로그인 필요). 정확한 메뉴는 그 시점에 확인해 안내한다.

## 8. 테스트 방법

- 프런트에 테스트 러너가 없다(`package.json` 확인). 거리 계산·정렬·필터·네이버 링크 생성은 순수 함수로 분리하고 `node --test`로 돌리는 작은 테스트 파일을 둔다(새 의존성 없음).
- 수집기 정규화·자동 확정 규칙은 `pytest` 없이 `python -m unittest`로 표본 30개 장소명을 검사한다.
- 화면은 내장 브라우저 미리보기에서 `navigator.geolocation`을 스크립트로 대체해 위치 허용·거부·지연 세 경우를 확인한다.
