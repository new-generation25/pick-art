# pica 커뮤니티 참여·포인트·등급제 제안 (2026-11-01)

> **결정 사항 (2026-11-01, 사용자)**
> 1. 매달 활동 자격: 제보 1건 승인, 후기 1건, **댓글 3개 이상** 중 하나
> 2. 미활동한 달은 **혜택을 주지 않는다**(레벨·포인트는 유지)
> 3. **현금성 포인트 전환을 허용한다** (7절 "포인트 전환" 참고)
> 4. 0단계 보안 정비를 시작한다

## 결론

- **가입은 바로, 자격은 활동으로.** 가입하면 누구나 보고 댓글을 달 수 있다. 매달 정보 제보·후기·댓글 중 하나 이상을 해야 "활동 회원" 상태와 그 혜택이 유지된다.
- **두 축으로 나눈다.**
  1. **레벨**: 쌓은 포인트로 오르고, 내려가지 않는다. 네이버 카페의 등업처럼 오래 쌓은 기여를 인정한다.
  2. **활동 상태**: 매달 다시 판정한다. 활동이 없으면 레벨은 그대로 두고 혜택만 쉰다. 활동을 1건 하면 바로 돌아온다.
- **"정보가 맞는가"를 따로 잰다.** 당근 매너온도처럼 다른 사람의 평가가 쌓이는 신뢰 지표(정보 정확도)를 둔다. 포인트가 많아도 틀린 정보를 올리면 권한이 오르지 않는다.
- **보상은 현금보다 기회로 시작한다.** 이달의 리포터 선정, 초대권 추첨, 큐레이션 노출, 인스타 콘텐츠 협업 등이다. 현금성 포인트는 운영비와 세무 처리가 생기므로 2단계로 미룬다.
- **먼저 해야 할 일**: 지금 DB 권한이 "누구나 읽고 쓰기(Allow All)"이고 관리자 화면에 권한 검사가 없다. 사용자가 글을 올리기 전에 이것부터 막아야 한다.

## 2. 참여 방법과 포인트

| 활동 | 포인트 | 조건 | 하루 한도 |
|---|---|---|---|
| 행사 정보 제보 | 300 | 운영진 승인 시 지급. 공식 링크 포함 +100, 포스터 포함 +100 | 3건 |
| 관람 후기 | 글 100 / 사진 200 | 행사 1건에 1회. 현장 인증(티켓·현장 사진·위치) +100 | 5건 |
| 정보 정정 제보 | 100 | 날짜·장소·링크 오류를 알려 주고 승인되면 지급 | 5건 |
| 댓글 | 10 | 10자 이상 | 10개 |
| 받은 "도움돼요" | 5 | 내 제보·후기에 다른 회원이 누른 것 | 월 500 |
| 출석·방문 | 0 | 방문만으로는 주지 않는다(포인트 부풀리기 방지) | - |

- 포인트는 **승인 후 지급**한다. 후기·댓글은 24시간 안에 신고가 없으면 확정한다.
- 신고로 삭제된 글은 포인트를 회수하고 정확도에 반영한다.
- **단계 미션**(MY플레이스 방식): 첫 제보 승인 +200, 후기 5·10·20건 달성 +300·+600·+1,200
- 2026-11-01 시뮬레이션(`docs/points/points-simulation.html`)으로 단가를 약 10배로 올렸다. 옛 단가로는 보통 회원이 5,000P 첫 전환까지 약 5년 걸렸다.

## 3. 등급 (레벨: 쌓이면 오르고 내려가지 않음)

| 레벨 | 이름 | 오르는 조건 | 할 수 있는 것 |
|---|---|---|---|
| 1 | 관객 | 가입 | 보기, 찜, 댓글, 후기, 제보(운영진 검토 후 노출) |
| 2 | 단골 | 누적 100P + 활동한 달 2개월 | 사진 댓글, 후기 상단 노출 우선 |
| 3 | 리포터 | 누적 300P + 제보 승인 5건 + 정확도 90% 이상 | **제보 즉시 노출**(사후 검수), 리포터 배지 |
| 4 | 큐레이터 | 누적 1,000P + 후기 20건 + 최근 3개월 신고 0건 | 추천 목록(큐레이션) 작성, 홈 "큐레이터 픽" 노출 |
| 5 | 지역 앰배서더 | 운영진 선정(시군별 1~3명) | 기관 초대권·프레스 기회, 인스타 콘텐츠 협업, 지역 운영 참여 |

1~4단계는 조건을 채우면 자동으로 오른다. 5단계만 운영진이 선정한다(네이버 카페의 "신청 후 승인" 방식).

## 4. 매달 활동 자격 (제안하신 개념)

- **이번 달 활동 회원**: 그달에 제보 1건 승인, 후기 1건, 댓글 3개 중 하나를 채우면 된다.
- 활동 회원에게만 주는 혜택:
  - 레벨별 권한(리포터 즉시 노출 등)
  - 이달의 리포터·초대권 추첨 응모
  - 프로필의 "이번 달 활동" 표시
- **활동하지 않은 달에는 혜택을 주지 않는다** (결정 사항 2).
  - 레벨과 포인트는 그대로 둔다.
  - 그달에는 레벨 권한(즉시 노출, 큐레이션), 추첨 응모, 포인트 전환을 쓸 수 없다.
  - 활동 기준을 채우면 그날 바로 돌아온다.
- 가입을 막거나 레벨을 깎지 않는 이유: 계정을 지우거나 등급을 떨어뜨리면 다시 오지 않는다. 혜택을 쉬게 해야 돌아올 이유가 남는다. 처음 3개월은 이 규칙만 돌리고, 지표를 본 뒤 조정한다.

## 5. 신뢰 지표: 정보 정확도

- 제보 승인율, 정정 제보로 바뀐 비율, 신고 처리 결과로 계산하고 프로필에 %로 표시한다.
- 처음 5건까지는 "새 리포터"로만 표시한다(표본이 적을 때 숫자가 흔들리지 않게).
- 90% 미만이면 3단계 권한(즉시 노출)을 주지 않는다. 70% 미만이면 제보를 운영진 검토 대기로 되돌린다.

## 6. 지역 인증 (당근 동네인증 방식)

- 휴대폰 위치로 시군을 한 번 인증하면 "김해 주민" 같은 배지를 단다. 6개월마다 다시 인증한다.
- 인증한 지역의 행사 후기와 제보에 "주민" 표시가 붙는다.
- 위치는 시군 이름만 저장하고 좌표는 저장하지 않는다.

### 포인트 전환 설계 (현금성, 골목상권 사용)

- 비율과 문턱: 1P = 1원 상당, **3,000P부터** 전환, 1인 월 **30,000P 한도**
- 자격: 레벨 2(단골) 이상, 그달 활동 회원, 정확도 70% 이상
- 사용처는 골목상권으로 한정한다(사용자 지시, 2026-11-01). 편의점·대형 프랜차이즈 기프티콘과 계좌 현금은 주지 않는다.
  1. **pica 제휴 골목 가게 교환권**(먼저): 공연장·전시장 근처 카페·책방·밥집의 3,000/5,000/10,000원 교환권을 pica가 액면가로 사서 지급한다. 교환권은 각 가게가 발행하므로 pica가 여러 가게용 결제수단을 직접 발행하는 구조를 피한다.
  2. **온누리상품권(모바일)**: 전통시장·골목형상점가. 법인 구매·지급 조건 확인 필요.
  3. **지역사랑상품권**(김해사랑상품권 등): 법인이 사서 회원에게 지급할 수 있는지 시군 확인 필요.
- pica 포인트를 여러 가게에서 바로 결제받게 하지 않는다. 2024-09 시행 개정 전자금융거래법에서 가맹점 수 기준 등록 면제가 1곳으로 줄었다. 법률 검토 전에는 가게별 교환권 방식이 안전하다.
- 처리: 전환 신청 → 운영진 확인(부정 적립 검토) → 매월 1회 일괄 지급. 지급 내역은 `point_ledger`에 남긴다.
- 세무: 회원이 받는 보상은 기타소득으로 볼 수 있고, 금액 기준에 따라 원천징수가 필요할 수 있다. 지급 규모가 정해지면 세무 확인을 받는다.
- 예산: 월 지급 총액 상한을 정하고(예: 월 30만 원), 상한에 닿으면 다음 달로 넘긴다.

## 8. 남용 막기

- 하루 한도, 같은 행사에 후기 1회, 승인 후 지급, 24시간 신고 기간
- 신고 3건이면 자동으로 숨기고 운영진이 검토한다. 허위 제보가 반복되면 정확도와 권한을 낮춘다.
- 새 계정은 첫 7일 동안 하루 제보 1건으로 제한한다.
- 사진 저작권: 포스터는 "공식 홍보물 출처 표기"를 조건으로 받고, 남의 사진을 올리지 않는다는 약관 동의를 받는다.

## 9. 만들 것 (지금 코드 기준)

지금은 사용자가 글을 올리는 기능이 없다. 테이블은 `events`·`raw_posts`·`profiles` 등뿐이다.

| 항목 | 내용 |
|---|---|
| 선행 보안 | 모든 테이블의 RLS를 "본인 글만 쓰기·수정, 공개 글만 읽기"로 바꾼다. 관리자 화면에 `profiles.role='admin'` 검사를 넣는다 |
| 테이블 | `submissions`(제보, 승인 상태), `reviews`(후기, 사진, 현장 인증), `comments`, `reactions`(도움돼요·찜), `point_ledger`(포인트 원장: 사유·대상·증감), `reports`(신고) |
| profiles 추가 | `points`, `level`, `active_until`(활동 자격 기한), `accuracy`, `verified_region` |
| 화면 | 행사 상세의 후기·댓글, 제보 폼(링크 붙여넣기 → 수집기로 날짜·포스터 자동 채움), 내 활동·포인트, 관리자 제보 승인함 |
| 자동 처리 | 매일: 신고 기간이 지난 포인트 확정. 매달 1일: 활동 상태·레벨 판정, 이달의 리포터 후보 집계(수집기 `main.py` 일정에 붙이거나 Supabase pg_cron) |

### 11-1. 단체 계정과 단체 포인트

- 대상: 극단·공연 단체·전시 공간·문화재단·축제 추진위. 고유번호증·사업자등록증 또는 공식 SNS 계정으로 확인한다.
- **행사 등록은 무료**로 둔다. 단체가 직접 올리면 날짜·장소·예매 링크가 정확해지고, 자동 수집이 놓치는 작은 공연이 들어온다.
- 단체도 포인트를 받는다(가정값):
  - 행사 직접 등록 승인: 1,000P (월 5건까지)
  - pica 회원 전용 혜택 개설: 1,000P
  - 회원이 그 혜택을 사용: 1건당 100P
- **단체 포인트는 pica 홍보 상품에만 쓴다.** 현금으로 바꾸지 않는다.
- **포인트가 모자라면 그 차액을 현금(카드)으로 그때 결제한다.** 현금을 미리 넣어 포인트로 쌓아 두는 충전은 두지 않는다. 충전을 두면 선불전자지급수단이 될 수 있어서다.

### 11-2. 홍보 상품 (유료 전환 후. 가격은 가정, 시뮬레이션 6절에서 조정)

| 상품 | 내용 | 가격 |
|---|---|---|
| 상단 노출 7일 | 그 행사가 속한 날짜 묶음 맨 위, "제휴" 표시 | 30,000P |
| 주간 뉴스레터 소개 | 구독자 메일 1회 | 20,000P |
| 큐레이터 픽 | 홈 "큐레이터 픽" 칸 7일, 소개글 | 50,000P |
| 인스타 @picka.news 소개 | 카드뉴스 또는 릴스 1건 | 100,000P |

- 돈을 받은 노출에는 반드시 "제휴" 또는 "광고"를 표시한다(표시광고법). 표시가 없으면 회원 추천과 광고가 섞여 정보 신뢰가 무너진다.
- 큐레이터 픽을 팔지 여부는 따로 정한다. 회원 큐레이터가 고른 칸과 산 칸이 같은 자리에 있으면 4절 레벨 4의 의미가 약해진다.

### 11-3. 단체 이벤트 연계: "pica 보고 왔어요"

- 단체가 pica 회원 전용 혜택을 연다: 현장 할인, 예매 할인 코드, 초대권 추첨, 굿즈.
- **사용은 봉황 메모리즈 방식**: 매표소·안내데스크에 스티커 QR 한 장을 둔다. 회원이 찍으면 확인 화면 → [사용하기] → "사용 완료" 화면을 직원에게 보여 준다. 단체 쪽은 기기도 로그인도 필요 없다.
  - 찍었다고 바로 쓰이지 않는다(확인 버튼). 지갑 주인 계정만 쓸 수 있다(캡처 전달 방지).
- 예매 할인 코드는 단체가 쓰는 예매처의 코드를 pica 회원에게만 보여 준다. 사용 건수는 코드별로 단체에게 받는다.
- 할인 부담은 단체가 진다(단체의 홍보비). pica는 단체 화면에 **혜택 사용 건수와 pica를 거쳐 간 예매 클릭 수를 나란히** 보여 준다. 봉황 메모리즈에서 "얼마를 냈는가"만 보면 이탈하고 "얼마를 받았는가"를 함께 봐야 남는다고 정리한 것과 같은 이유다.
- 회원이 혜택을 쓰고 후기를 남기면 현장 인증 후기로 친다(+100P).

### 11-4. 회원 포인트 사용처에 봉황 방식 적용

- 골목 가게 교환권(7절 1번)을 스티커 QR로 바꾼다. 가게 카운터에 스티커를 두고, 회원이 찍어 포인트를 차감한다(1P=1원, 3,000P부터).
- 유효기간 6개월, 먼저 받은 것부터 소진. 만료는 배치로 지우지 않고 읽을 때 판정한다(봉황과 같음).
- 가게 부담 비율(충당률)은 시범 기간 0%로 시작한다. 사용 시점의 비율과 분담액을 기록에 복사해 둔다. 가게 월 상한을 넘어도 사용은 막지 않고, 넘은 몫은 pica가 진다.
- **주의**: 이 방식은 7절에서 피하자고 한 "pica 포인트를 여러 가게에서 바로 쓰는" 구조다. 봉황 메모리즈도 같은 구조이므로 두 프로젝트를 한 번에 법률 검토 받는다. 발행 규모가 작으면 등록을 면제하는 금액 기준이 있지만 확정 수치와 조건은 아직 확인하지 못했다.

### 11-5. 나중: pica에서 직접 결제·정산

- 예매·결제를 pica에서 받고 단체에 정산한다. 필요한 것: PG 계약, 통신판매중개업 신고, 환불 규정, 정산 주기(예: 공연 종료 후 7일), 수수료율.
- 이 단계에서 회원 포인트를 티켓값에 쓸 수 있게 한다. 포인트 사용분은 pica가 단체에 현금으로 정산한다.
- 시작 조건: 홍보 상품을 쓰는 단체가 20곳 이상이고, "pica 보고 왔어요" 사용 기록으로 유입을 숫자로 보여 줄 수 있을 때.

### 12-1. 숨은 행사 제보 (진행)

  1. **피카 사이트에서 직접**: 공개 화면 아래쪽에 「행사 제보하기」 버튼을 크게 둔다. 제보 화면은 단순하게(행사 이름 · 원문 링크나 사진 하나 · 날짜·장소는 선택 · 쿠폰 받을 연락처는 선택+동의). 지금 /tip 은 로그인해야 보낼 수 있어 문턱이 높다 → 「피카 앱 개선」 세션에 요청(2026-11-27).
  2. **카카오톡으로 보내기 안내**: 카카오톡 채널 «피카»(검색 ID pickanews)의 「행사 알리기」로 사진·글을 보내게 안내한다(specs/017 챗봇, 이미 동작).

- 결론: **반자동** — 응모 수집·추첨·기록은 도구로, 주최 측 확인·당첨 연락·명단 전달은 사람이(또는 사람이 확인한 뒤).

### 12-3. 단체 대상 — 먼저 소개 + 소식 지속 제공 안내 (진행)

- 「이번 주 작은 무대」: /partners 로 신청했거나 허락받은 소규모 단체 행사를 그 주 피드·스토리에서 **먼저** 소개한다(INSTA_DAILY 비율 50:50 안에서 소규모 몫을 먼저 채움).
- 소식 지속 제공 안내: 한 번 소개한 단체에 「앞으로의 소식도 계속 실어 드려요 — 원하시면 /partners 에서 동의, 언제든 철회 가능」을 안내한다. 정식 동의 절차(memory: 「formal consent later」, /partners 동의 칸 specs/016)와 같은 길로 받는다. 안내를 보내는 **시점은 운영자가 정한다**.
- 단체 안내 게시물(피드 1편)은 기획서를 먼저 운영자에게 보여 준 뒤 만든다(인스타 스킬 순서).

### 12-4. 「직접 다녀왔어요」 (나중을 위한 계획)

- 운영자가 한 달에 두 곳, 관객이 적은 작은 공연을 직접 보고 사진 1장 + 한 줄 후기(줄 서는 시간·주차·분위기)를 「직접 다녀왔어요」 표시로 올린다(BRAND_GUIDE 13절 「사람의 흔적」). 비용은 관람료뿐.
- 시작 시점은 운영자가 정한다. 시작하면 INSTA_DAILY 에 절차를 옮긴다.
