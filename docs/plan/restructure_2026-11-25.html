3. 뿌리 문제 넷

① 돌았는지·비정상인지 판정하는 곳이 없다

실행 결과는 로그 파일과 텔레그램 글에만 있고 DB에는 없다(정기 실행은 crawl_logs에 쓰지 않는다). 그래서 «KOPIS 0건 2회 연속», «아침 회차 누락», «정의 만료 의심 3일째» 같은 판정을 아무도 하지 않는다.

② 사람 판단 대기열이 다섯 군데다

인박스 73 · 인스타 REVIEW 663 · 장소 확인 · 정의 만료 · 허락 답 대기 47(인스타 리포트). 어디부터 볼지 한 화면에 없다.

③ 이 PC와 외장 SSD에 묶여 있다

실행 누락과 운영 기록 무백업이 둘 다 여기서 온다.

④ 코드 정리가 밀렸다

일회성 스크립트 71개(수집기 37 + 루트 34), Streamlit admin/, .agent/, testsprite_tests/, 쓰지 않는 화면·API(ai-prompt, getPrompt/updatePrompt, 구독자 0명인 뉴스레터, 쓰지 않는 pg 의존성, page.tsx.backup), 같은 숫자를 보여 주는 /admin과 /admin/stats. 위험보다 «어느 것이 지금 쓰는 것인지 모른다»가 문제다.

7. «앱코딩» 세션에서 가져온 것

  • 포인트·커뮤니티 제도(docs/PLAN_community_2026-11.md, docs/points/)는 문서만 있고 앱 구현 전이다. 이번 계획에는 넣지 않고, D1 대시보드에 그 기준 숫자(가입 회원 1만 명)만 넣는다
  • 검색창 X 버튼은 배포돼 있다. 그때 알린 두 가지는 아직 그대로다: 관리자 화면 검색창 4곳(blacklist·whitelist·sources·subscribers)에는 X가 없고, 지역·분야 필터를 건 채 검색어를 Enter로 보내면 필터가 풀린다(SearchBox가 q만 보냄). 둘 다 이번 계획 밖이라 손대지 않는다
  • 그 세션이 «관리자 화면에 가입 회원 수를 보여 주는 자리가 있는지는 확인하지 않았다»고 남긴 부분: 지금 /admin·/admin/stats 어디에도 없다(확인함). D1에서 넣는다

운영자가 정할 것

  1. 대시보드 범위 — (a) 앱 관리자 운영 대시보드를 먼저 만들고 인스타 지표는 R3에서 합치기 [추천] / (b) 인스타 리포트 이전만 / 둘을 처음부터 같이(새 테이블 먼저 승인 필요)
  2. 이 계획과 순서 승인 — R0 → D1 → R1 → R2 → R3 → R4 → R5 (R6은 나중)
  3. D1 화면 확인용 개발 서버 — 메모리 상한 2GB로 띄우고 스크린샷 뒤 끈다
  4. 단계 안에서 따로 묻는 것(그 단계에 들어갈 때 다시 묻는다): 스케줄러 설정 · 백업 위치 · 새 테이블 · 파일 이동 목록 · 접을 폴더와 지울 화면
